Warm-up: The Translator Story

Imagine a student who speaks only Urdu wants to talk to a person who understands only English. They cannot understand each other directly. So they ask a translator.

A computer is in the same situation. Programmers write in languages like C (easy for humans). The computer's processor (CPU) understands only machine instructions (0s and 1s). A compiler is the translator in the middle.

In the storyIn computing
Urdu speakerProgrammer writing C code
TranslatorCompiler

1. What is a compiler?

What is it?A compiler is a program that reads a program written in one language (the source language, e.g. C) and translates it into an equivalent program in another language (the target language, usually machine code). While translating, it also reports mistakes in your code.
Why do we need it?The CPU cannot read C. Writing machine code by hand is slow, tiring and full of mistakes. The compiler lets humans write easy code while the computer still gets what it needs.
How does it work?The compiler reads your whole program, checks it, translates it, and saves the result as a new file (the executable). Later, you run that file. Translation and running are two separate steps.
Everyday life
A translator turns a whole Urdu letter into an English letter. The English reader then reads the finished letter.
Computer science
The command gcc hello.c -o hello turns hello.c into the program hello (or hello.exe on Windows).
/* hello.c  -  our source program */
#include <stdio.h>
int main() {
    printf("Hello, Pakistan!\n");
    return 0;
}

Did you know? Grace Hopper built one of the very first compiler-like systems (the A-0 system) in 1952. Before that, programmers wrote numbers by hand for every instruction!

2. Why do we need a compiler?

What is it?A compiler is a bridge between human thinking and machine working.
Why do we need it?
  • Productivity: one line like c = a + b; replaces many machine instructions.
  • Fewer mistakes: the compiler finds many errors before your program runs.
  • Portability: the same C code can be compiled for different computers.
  • Speed: compilers optimize the program so it runs faster.
  • Hides hardware details: you do not need to know CPU registers.
How does it work?It analyses what you wrote, understands its meaning, then re-writes the same meaning in the computer's language.
Everyday life — restaurant
A customer says, “One chicken karahi, two naan.” The waiter writes a kitchen ticket in short chef-language. The chef follows the ticket. The waiter is like the compiler: customer language → kitchen instructions.
Computer science
You write total = price * qty;. The compiler turns it into instructions such as “load price, multiply by qty, store in total”, in the exact format your CPU understands.
Did you know? Why does a compiler report errors? Because it must understand your code completely before translating it. If a sentence is broken (like int = ;), it cannot be translated, so it tells you where the problem is. Error messages are the compiler helping you!

3. What is a programming language?

What is it?A programming language is a formal language with strict rules, used to give instructions to a computer. It has syntax (how sentences must be written) and semantics (what they mean).
Why do we need it?Human languages like Urdu or English can be unclear. (“I saw a man with a telescope” — who has the telescope?) A computer needs instructions with exactly one meaning.
How does it work?The language defines allowed words (keywords such as int, if), symbols and grammar rules. A translator checks your code against these rules.
Everyday life
A cooking recipe: “Add 2 spoons of salt.” It must be exact. “Add some salt, maybe” is not clear enough for a machine.
Computer science
printf("Hi"); follows C rules, so it is valid. print f(Hi breaks the rules, so the compiler rejects it.

Examples: C, C++, Java, Python, JavaScript. Each has its own rules, but all must finally be turned into something a CPU can run.

4. High-level vs low-level languages

What is it?High-level languages (C, Python, Java) look like human language and hide hardware details. Low-level languages (assembly and machine language) are close to the hardware.
Why do we need both?Humans prefer high-level code; the CPU runs only low-level machine code. Both levels exist, and the translator connects them.
How do they differ?Look at the same task (add two numbers) at three levels. Click the tabs:

What is it? A compiler translates the whole program into a target program before it runs. An interpreter reads the program and executes its statements directly while reading, step by step.
Why do both exist?Compilers give fast programs. Interpreters give quick start-ups and easy testing. Each is better for different jobs.

Why do we need it?No single tool does everything. Each helper does one job well: prepare, translate, convert, combine, load.

7. The role of language translation in the programming process

What is it?Language translation is the step that converts the code humans write into the instructions machines run.
Why do we need it?A CPU is made of billions of tiny electronic switches that are either ON (1) or OFF (0). Instructions must therefore be in binary form. Translation lets people think in C while hardware works in binary.
Where does it fit?Programming is a cycle: Write → Translate → Fix errors → Run → Test → Improve. Translation is the middle step where your ideas become machine instructions.
Animation 3: Language translation
Everyday life
Light switches in a room: each one is ON or OFF. A pattern like ON-OFF-ON can mean something. A computer reads billions of such patterns.
Computer science
Source code → translator → machine instructions → CPU. If you change the CPU type, the translator must produce different machine code.
Did you know? How does a compiler help programmers? It checks spelling and grammar of your code, finds many logic problems early, and makes your program faster — all automatically.

8. Inside the CPU: fetch, decode, execute

What is it?Once the compiler has produced machine code, the CPU runs it in a loop of three small actions: fetch the next instruction from memory, decode what it means, and execute it. Then it repeats.
Why should a compiler student care?This loop is the compiler's customer. Every instruction the compiler writes must be something this loop can run. Fewer and simpler instructions mean a faster program.
How does it work?The CPU keeps a program counter (PC) that points to the next instruction, and a few registers, which are tiny storage boxes inside the chip. Watch them change below.

9. Compilers around you today

You used several compilers before breakfast. Here is where they hide in the apps on your phone and laptop.

Chrome and JavaScriptChrome's V8 engine starts running JavaScript in an interpreter (Ignition), then compiles the busy parts to machine code while the page is open (Sparkplug, Maglev, TurboFan). That is a JIT compiler.
Android appsKotlin or Java is compiled to DEX bytecode. On the phone, the Android Runtime (ART) turns it into ARM machine code, partly at install time and partly while the app runs.
WebAssemblyC, C++ and Rust programs can be compiled to WebAssembly and run inside a browser tab. Figma and the web version of Photoshop work this way.
TypeScriptThe TypeScript compiler checks types and outputs plain JavaScript. A source-to-source compiler like this is called a transpiler. In 2025 Microsoft announced a rewrite of it in Go for much faster builds.
PythonCPython compiles your file to bytecode first, then a virtual machine runs the bytecode. Python 3.13 (2024) added an experimental JIT compiler.
RustThe Rust compiler refuses to build code that could use memory unsafely. A whole class of crashes is caught at compile time, before the program ever runs.
GamesEngines such as Unreal are written in C++ and compiled ahead of time for your phone's ARM64 chip, because games need every bit of speed.
AI modelsA neural network is also a program. Tools such as XLA, TVM and MLIR compile models into fast code for GPUs and phone chips.

10. Reading real error messages

What is it?An error message is the compiler telling you where it got confused, what it expected and often how to fix it. Modern compilers even draw an arrow under the exact spot.
Three real messagesThese are what the actual tools print. Click the tabs.
hello.c: In function 'main':
hello.c:4:30: error: expected ';' before 'return'
    4 |     printf("Hello, Pakistan!")
      |                              ^
      |                              ;
    5 |     return 0;
      |     ~~~~~~
A syntax error, found at compile time. Nothing ran. File hello.c, line 4, column 30, and GCC even suggests the missing ;.
error[E0308]: mismatched types
 --> src/main.rs:2:20
  |
2 |     let age: i32 = "Hello";
  |              ---   ^^^^^^^ expected `i32`, found `&str`
  |              |
  |              expected due to this
A semantic (type) error, also at compile time. The grammar is fine, but text can't go into a 32-bit integer.
Hello
10
Traceback (most recent call last):
  File "prog.py", line 4, in <module>
    print(y)
          ^
NameError: name 'y' is not defined
A run-time error. Lines 1 to 3 already ran and printed their output before Python reached the problem on line 4.

How to read any error message:

  1. Find the file, line and column (for example hello.c:4:30).
  2. Read the kind of problem: expected ';', mismatched types, not defined.
  3. Look at the arrow (^). The real mistake is at the arrow or just before it.
  4. Fix the first error and compile again. Later errors are often caused by the first one.

Knowledge check — Lecture 1

Key takeaways
  • A compiler translates a source program into a target program (usually machine code) and reports errors.
  • CPUs understand only machine instructions, so translation is essential.
  • High-level languages are human-friendly; low-level languages are hardware-friendly.
  • Compilers translate first, then run; interpreters execute statement by statement. Many systems use both.
  • A language processing system = preprocessor + compiler + assembler + linker + loader.
  • Modern systems mix styles: ahead-of-time (C, Rust), just-in-time (JavaScript, Java) and bytecode (Python).
  • The CPU runs machine code in a fetch, decode, execute cycle.
LECTURE 2

Organization and Basic Concepts of Compiler Construction

… 10 topics 5-question quiz

What happens when you click “Run”?

You write a C program, you press Run… and a moment later the output appears. It feels like magic. But behind that button, a chain of small tools works one after another. Your program makes a journey:

Source code → Preprocessor → Compiler → Assembler → Linker → Loader → Running program.

In this lecture you will meet each traveller on the road, learn what they do, and watch the journey happen.

1. Organization of a compiler

What is it?The organization of a compiler describes how it is built from smaller parts. Most compilers have two big halves: an analysis part (understand the source) and a synthesis part (build the target).
Why do we need it?Splitting a big job into small parts makes the compiler easier to build, test and reuse. For example, one analysis part can be shared by many target machines.
How does it work?Source program → Front end (analysis) → Intermediate representation → Back end (synthesis) → Target program. Two helpers work with every part: the symbol table (a notebook of names) and the error handler.

Everyday life
A restaurant has a front (understand the customer's order) and a kitchen (cook the meal). A notebook of regular customers is shared by both.
Computer science
The C front end can be combined with different back ends to make programs for Intel PCs or ARM phones. (Full details in Lecture 3.)

2. Basic concepts of compiler construction

What is it?Before building a compiler, we need a few basic words. Learn these and everything else becomes easier.
Source language
The language being translated (e.g. C).
Target language
The language produced (e.g. machine code or assembly).
Implementation language
The language the compiler itself is written in (e.g. C or C++).
Translator
Any program that converts one language to another. A compiler is a kind of translator.
Analysis and synthesis
Analysis = break the source into pieces and understand it. Synthesis = build the target program from that understanding.
Symbol table
A table storing information about names (variables, functions): type, scope, etc.
Error handling
Detecting, reporting and recovering from mistakes so many errors can be shown in one run.
Pass
One complete reading of the program. A compiler may use one pass or several passes.
Everyday life
Source language = Urdu, target language = English, translator = a person who knows both.
Computer science
gcc: source language C, target language x86-64 machine code, implementation language C/C++.
Did you know? Compilers are often built with helper tools such as Lex/Flex (for tokens) and Yacc/Bison (for grammar). You describe the rules; the tool writes much of the code!

3. Context of a compiler — the full pipeline

What is it?The context of a compiler means the other tools around it. The compiler never works alone. It is one stop in a longer pipeline.

4. Preprocessor

What is it?The preprocessor runs before real compilation. It handles lines starting with #: header file inclusion (#include), macro expansion (#define) and conditional compilation (#ifdef).
Why do we need it?It lets us reuse code from other files, give names to constants, and include or skip code for different situations.
How does it work?It does simple text replacement: paste the header's text, replace macro names by their values, remove unwanted code. Then it passes plain C to the compiler.
#include <stdio.h>
#define PI 3.14

int main() {
    printf("%f", PI);
    return 0;
}

 5. Compiler (translating to a lower level)

    
What is it?The compiler takes the expanded source and translates it into a lower-level representation, often assembly code. On the way it checks the program (Lecture 3 shows how).

    
Why do we need it?It is the main translator: it turns human ideas into a form close to the hardware and finds mistakes.

    
How does it work?Analyze the code, understand it, optimize it, and write the equivalent assembly.

 6. Assembler

    
What is it?An assembler converts assembly language (readable instructions like mov) into object code (binary machine code).

    
Why do we need it?The CPU cannot read the word mov; it needs a number pattern. The assembler does this word-to-number conversion.

    
How does it work?It looks up each instruction in the CPU's instruction table and writes the matching bytes into an object file (.o or .obj).

 7. Link editor (Linker)

    
What is it?The linker (link editor) combines one or more object files and library code into one executable file. It also connects each function call to the real function.

    
Why do we need it?Big programs are split into many files, and we also use library functions like printf. Someone must join the pieces.

    
How does it work?Object files contain “holes” (unresolved references). The linker finds where each function lives, decides final addresses, and fills the holes.




main.c
int add(int a, int b);  // only a promise

int main() {
    return add(2, 3);
}


math.c
int add(int a, int b) {
    return a + b;
}




gcc -c main.c            # makes main.o
gcc -c math.c            # makes math.o
gcc main.o math.o -o app # linker joins them into app

 8. Loader

    
What is it?The loader (part of the operating system) copies the executable from disk into memory (RAM) and starts it.

    
Why do we need it?The CPU runs programs from RAM, not directly from disk. Something has to move the program there and prepare it.

    
How does it work?The loader reads the file header, reserves memory, copies code and data, prepares stack and heap, then jumps to the program's starting point (main).

Reading a sentence: first see the words, then check the grammar, then check it makes sense, then retell it in another language.

      
 Computer science
Phases 1–3 analyze the source (find structure and meaning). Phases 4–6 synthesize the target program.

    

    
 Did you know? In real compilers the phases are often interleaved (the parser may call the lexer on demand). Showing them as separate boxes is a teaching model.

  


  

    
 Phase 1: Lexical analysis (Scanner)

    
What is it?The lexical analyzer (scanner) reads the characters of your program and groups them into meaningful words called tokens. It also removes spaces and comments.

    
Why do we need it?Later phases should work with words, not single letters. Grouping letters into tokens makes grammar checking much easier.

    
Token types
      Keyword reserved words (int, if, return)
      Identifier names you choose (total)
      Operator = + - * /
      Constant 10, 3.5, 'A'
      Separator ; , ( ) { }
    

    
For int total = 10 + 20; the tokens are: int keyword · total identifier · = assignment operator · 10 integer constant · + arithmetic operator · 20 integer constant · ; separator.

    

      
 Everyday life
Splitting “I am going home” into words: I | am | going | home.

      
 Computer science
int x=5; (no spaces) is still split correctly into 5 tokens: int x = 5 ;.

 Phase 2: Syntax analysis (Parser)

    
What is it?The parser checks whether the tokens follow the grammar (the sentence rules) of the language and builds a syntax tree showing the structure.

    
Why do we need it?Words alone are not enough: “home going I am” has the right words in the wrong order. The parser catches such structure mistakes (syntax errors).

    
How does it work?It uses grammar rules. Our beginner grammar:

statement  → [type] ID '=' expression ';'
expression → term   ( ('+' | '-') term )*
term       → factor ( ('*' | '/') factor )*
factor     → NUMBER | ID | STRING | CHAR | '(' expression ')'

      Because * is handled lower in the tree than +, multiplication happens first (correct precedence).

    

      
 Everyday life
A sentence needs a subject and a verb in the right order. “Ali the ball kicked” has the wrong structure.

      
 Computer science
int x = 10 + ; — the + is waiting for a second value that never comes: syntax error.

 Phase 3: Semantic analysis

    
What is it?Semantic analysis checks that the program makes sense: types match, variables are declared before use, functions get the right arguments.

    
Why do we need it?A sentence can have perfect grammar and still be nonsense (“The table drank the song.”). Code is the same.

    
How does it work?It walks the syntax tree and uses the symbol table to check types and declarations.


int age = "Hello";   // grammar is fine, but the meaning is wrong

    
Here age is an int (a whole number), but "Hello" is text. In C, storing text in an integer variable is a type mismatch.

 Phase 4: Intermediate code generation

    
What is it?The compiler converts the syntax tree into a simple, machine-independent form called intermediate code. A popular form is three-address code: each line has at most one operator.

    
Why do we need it?It is a neutral middle language: easy to optimize and easy to translate to many different CPUs.

    
How does it work?Complex expressions are broken into small steps using temporary variables (t1, t2, …).


a = b + c * d;


t1 = c * d      // t1 holds the result of c * d  (multiplication first)
t2 = b + t1     // t2 holds b + (c * d)
a  = t2         // finally store into a

    

      
 Everyday life
Solving a long maths problem on paper: write each small result on its own line before the final answer.

      
 Computer science
Temporary variables t1, t2 are just names for intermediate results. They may later live in CPU registers.

 Phase 5: Code optimization

    
What is it?Optimization improves the intermediate code so the final program is faster or smaller — without changing what it does.

    
Why do we need it?Programmers write readable code, not always the fastest code. The optimizer cleans it up automatically.

    
How does it work?It looks for patterns it can simplify. Two simple ones: constant folding (calculate constants at compile time) and algebraic simplification (e.g. x + 0 = x).

 Phase 6: Code generation

    
What is it?Code generation turns the (optimized) intermediate code into target code — assembly or machine instructions for a specific CPU.

    
Why do we need it?This is where the program finally becomes something the processor can execute.

    
How does it work?It chooses CPU instructions, decides which registers (tiny super-fast storage inside the CPU) to use, and lays out memory.

    
Intermediate codeTarget code (illustrative)

    

    
Important noteThis pseudo-assembly is only an illustration. Real instructions depend on the processor and the compiler. A real x86-64 compiler might produce something like:

mov eax, [c]
imul eax, [d]
add eax, [b]
mov [a], eax

    

      
 Everyday life
A recipe is rewritten for a specific kitchen: gas stove vs electric oven needs different steps.

      
 Computer science
The same intermediate code produces different instructions for Intel x86-64 and for ARM.

 3–4. Front end and back end

    
What is it?The six phases are grouped into two halves: the Front End (understands the source program) and the Back End (builds the target program).

    
Why do we need it?The front end depends on the source language; the back end depends on the target machine. Separating them lets us mix and match.

    

      
 FRONT END source-dependent
  • Lexical analysis
  • Syntax analysis
  • Semantic analysis
  • Intermediate representation
Understands and analyzes the source program.

      
 Intermediate representation (the bridge)

      
 BACK END target-dependent
  • Code optimization
  • Target code generation
Optimizes and generates target-specific code.

    

    

    

      
 Analogy
Front end = understanding the customer's order. Back end = preparing the actual meal using the kitchen equipment.

      
 Computer science
Compilers such as GCC and LLVM reuse one back end for many languages, and one front end for many CPUs.

    

    
Not a hard wallWhere exactly intermediate code and optimization sit depends on the compiler's design. Many compilers do some optimization on a machine-independent IR (front side) and more on target code (back side). So the boundary can vary.

Why the split matters: m languages × n machines

    
Without a shared intermediate form you need a separate compiler for every language–machine pair. With one, you need only one front end per language and one back end per machine.

    

      

      

      

    

  


  

    
 Real architecture: the LLVM route map

    
What is it?LLVM is a real, widely used compiler framework built exactly on the front end / IR / back end idea. Many languages have their own front end, and they all share one optimizer and one set of back ends.

    

      
 Click a language on the left and a CPU on the right

      

      

      
4 front ends + 4 back ends = 8 components, but 4 × 4 = 16 working compilers. This is the m × n saving from the previous topic, in real life.

    

    
A modern idea in one minute: SSAModern optimizers rewrite the IR so that every variable is assigned exactly once. This is called static single assignment (SSA). It makes it easy to see where each value comes from.

x = 1          x1 = 1
x = x + 5  →   x2 = x1 + 5      // each name has one definition
y = x * 2      y1 = x2 * 2

    
 Did you know? Give Clang a loop that adds the numbers 0 to n-1 and turn on -O2. It can remove the loop completely and compute the answer with a formula, n(n-1)/2. GCC uses the same three-part design with its own IR, called GIMPLE.

 5. Important definitions

    
    
      
  • Compiler: translates a whole source program into a target program and reports errors.
    • 
      
  • Interpreter: executes a program statement by statement as it reads it.
    • 
      
  • Token: the smallest meaningful unit of a program (keyword, identifier, operator, constant, separator).
    • 
      
  • Parser: checks grammar and builds the syntax tree.
    • 
      
  • Semantic analysis: checks meaning such as types and declarations.
    • 
      
  • Intermediate code: machine-independent code such as three-address code.
    • 
      
  • Linker: combines object files and libraries into an executable.
    • 
      
  • Loader: places the executable in memory and starts it.
    • 
    

    
More terms are in the Glossary, and flashcards are waiting there too.

  


  

    
 6. Common mistakes students make

    
    
      
  1. Thinking the compiler runs the program. It only translates it; the CPU runs the result.
    2. 
      
  2. Mixing up the linker (combines code) and the loader (puts it in memory).
    3. 
      
  3. Saying an interpreter “never translates”. It still analyzes and translates internally.
    4. 
      
  4. Believing “no syntax error” means “correct program”. Meaning and logic can still be wrong.
    5. 
      
  5. Confusing assembler and compiler. The assembler translates assembly; the compiler translates a high-level language.
    6. 
      
  6. Thinking machine code works on every computer. It depends on the processor family.
    7. 
      
  7. Thinking the six phases never overlap. In real compilers they are interleaved.
    8. 
      
  8. Thinking optimization changes the output. It must keep the same behavior.
    9. 
      
  9. Calling a linker error (undefined reference) a compiler error.
